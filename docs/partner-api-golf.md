# 골프 서비스 결제 연동 작업 지시

작성 2026-10-27. 첨부: 사양서 `partner-api-golf.md` 최신본(§8 로그인 연동 포함)

제안하신 흐름(예약 내용 전달 → 본 사이트 결제창 → 결과 확인 → 예약 확정, 운행 취소 시 환불 API)으로 진행합니다.
자세한 사양은 첨부한 사양서를 따르고, 아래 순서로 구현해 주세요.
모든 API 호출은 **골프 서버에서** 하고, 브라우저에서 직접 호출하지 않습니다.

## 1. 로그인 연동 (사양서 §8)

- 골프 페이지 요청에 들어오는 `user_session` 쿠키 값을 `GET /api/partner/session` 에 `X-User-Session` 헤더로 보내 회원 정보를 받습니다.
- 응답이 404 `no_session` 이면 `/login?next=/golf/...` 로 보내 로그인 뒤 원래 화면으로 돌아오게 합니다.
- 자체 회원가입·로그인·로그아웃 화면은 만들지 않습니다. 로그아웃은 본 사이트 `/logout` 으로 보냅니다.
- 예약자 이름·이메일·전화는 응답값으로 자동 입력하고, **영문 이름은 골프 화면에서 직접 입력**받습니다.

## 2. 주문 생성 (§5)

- 예약 저장 후 `POST /api/partner/orders` 에 `reference`(골프 예약번호), `amount`, `title`(ja 필수), `user_id`, `return_url`, `departure_date`, `heads` 를 보냅니다.
- `amount` 는 골프 서버가 계산한 값만 보냅니다. 본 사이트는 검증 없이 그대로 청구합니다. 100엔 미만은 거부됩니다.
- 응답의 `order_id` 를 예약에 저장하고, 고객을 `checkout_url` 로 이동시킵니다.
- 409 `duplicate_reference` 가 오면 응답에 들어 있는 기존 주문을 씁니다.

## 3. 결과 확인 (§6)

- 고객이 `return_url` 로 돌아오면 `GET /api/partner/orders/{order_id}` 로 상태를 조회합니다. `return_url` 에 도착한 것만으로 성공 처리하지 않습니다.
- `paid` 일 때만 예약을 확정합니다. `failed`·`expired` 는 미결제 처리하고 좌석을 해제합니다.
- **`authenticating` 은 실패가 아닙니다.** 30초~1분 간격으로 몇 번 다시 조회하고, 그래도 미확정이면 "결제 확인 중" 으로 안내합니다.
- `pending`·`authenticating` 주문을 10분 주기로 재조회해 확정하는 배치를 만듭니다.
- 결제 확정 메일은 본 사이트가 보냅니다. 골프 쪽은 출발 확정·픽업 안내만 보냅니다.

## 4. 환불 (§7)

- 운행 취소나 고객 취소 시 `POST /api/partner/orders/{order_id}/cancel` 에 `reason`(`operator_cancel` / `customer_cancel`)을 보냅니다. `paid` 주문만, 전액만 환불됩니다.
- 409 `refused` 나 502 가 오면 실패를 기록하고 운영자에게 알립니다. 일괄 취소는 주문별로 순서대로 호출하고 실패 건을 재시도합니다.

## 5. 화면과 키 관리

- API 키는 환경변수로만 관리하고 소스·채팅·이슈에 적지 않습니다.

## 완료 기준 (테스트 서버에서 확인, §11)

1. 로그인 안 한 상태에서 골프 예약 화면 진입 → 로그인 → 원래 화면 복귀
2. 예약자 정보 자동 입력 확인
3. 주문 생성 → 결제 → 복귀 → 조회 API 로 `paid` → 예약 확정 표시
4. 3DS 화면에서 브라우저를 닫은 뒤 조회가 `authenticating` 을 돌려주고, 배치가 나중에 확정하는 것
5. 환불 호출 → `canceled`
6. 오류 케이스: 잘못된 키(401), 중복 reference(409), 미결제 주문 환불(409)
